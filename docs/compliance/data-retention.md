# APIデータの保存期限・削除・利用境界

> 文書ID：POL-001  
> 状態：作業1実装済み・モック検証済み（具体的な利用形態の監査未確認）\
> 読む場面：API由来データを保存・表示・出力・復元するとき  
> 整理日：2026-10-14  
> 元資料：[初回実装仕様 v2](../archive/codex_research_first_mvp_v2.md) L208–L221。見出し・参照リンクを整理し、要件の内容は引き継いでいる。

競合の統計は通常、チャンネル所有者の認可を得ていないデータ。公式ポリシーでは、特例がない非認可統計を30日を超えて保持しないことが明記されている。[W2](../references/sources.md#w2)

初期提案は、観測点を28日間のローリング保存とし、現行情報は更新すること。これは30日ルールに余裕を持たせる実装上の選択であり、28日が公式の基準という意味ではない。

**最新値を取得し直しても、古い観測点の取得日を書き換えて保存期限を延ばさない。** 競合の長期時系列分析は、追加許諾の条件を確認してから別対応とする。

ローカル停止後は、閲覧・集計より前に期限切れデータを削除または除外し、削除処理を実行する。ログ、キャッシュ、DBバックアップ、API由来の数値を転記した文章にも不要な長期コピーを残さない。

利用者自身の企画文章はAPIキャッシュと分ける。ただしAPIデータやその派生物を「手書きメモ」という名前に変えただけで保存制限から外す実装にはしない。

独自分析・分類や外部AI利用の適法・適合性を一律に断定しない。API由来の分類・独自評価等は初回の実装対象外とし、必要なら公式の確認・監査手順で解決する。[W1](../references/sources.md#w1)[W2](../references/sources.md#w2)

## 作業1の保存先と停止後の動作

現在情報・観測・取得実行（ページトークンを含む）は28日で失効する。取得実行に属する観測は、実行自体の期限で先に削除される場合もある。最新値の取得で以前の観測時刻・期限を書き換えない。

画面の処理と取得処理の前、および`youtube:prune`で期限切れをDBから削除する。参照されなくなった自動発見IDも削除する。利用者がウォッチ・目的記入・比較保存した対象はID参照のみを残し、公開データは残さない。

APIの応答本文をファイル・ログ・セッション・別キャッシュへ保存しない。通常のAPI失敗はサーバー側の分類コードだけを使い、元の例外・キー・URLを記録しない。DBキャッシュは処理の排他制御に使う。画面には`Cache-Control: no-store`を付ける。ローカル例外ログは既定7世代、停止後は削除処理で28日を過ぎたログファイルも除去する。

自動DBバックアップとAPIデータの書き出しは実装しない。手動で作ったDBダンプ・外部バックアップ等はアプリでは検出・削除できないため、APIデータの長期コピーを運用で作らない。復元した場合も表示前の期限削除は働く。自分の目的欄にはAPI数値・本文の転記を促さず、システムもコピーしない。

## 全動画継続観測への改修での優先契約（採用・未実装）

[TRK-002](../tracking/storage-and-jobs.md)のアクティブな対象参照は検索run削除と独立させる。上記「取得実行の期限で観測が先に削除される」「参照のない自動発見IDを削除」は旧実装の説明であり、新方式では検索期限を理由にアクティブ追跡や期限内観測を消さない。全動画を追い続けることと古い統計を保持することは別。

| データ種別 | 今回の期限・扱い |
|---|---|
| 統計の各観測 | observed_at起算28日。再取得で古い点を延命しない |
| メタデータ各版・検索所属 | その取得時刻起算28日、独立して失効。観測/検索の参照から内容を延命しない |
| 画像等の証跡 | 今回は取得保存無効。将来は許可・用途・取得時刻・独立した期限が必要 |
| API由来比較/分析/出力 | 含む根拠のexpires_atの最小値まで。失効後は数値・引用・派生内容を除外/削除し、根拠失効を示す |
| 本人企画・振り返り | 純粋な本人文とAPI由来部分を分離。手書きやファイルへの転記で期限を迂回しない |

長期統計、追加の独自分類・感情分析・AIへの送信/利用は、具体的用途の利用条件と必要な受理の証跡を確認するまで条件付き無効。確認先・確認日・対象データ/処理/送信先・期限・証跡を記録してから別途有効化する。手動でCodexへ渡す場合も同じ。今回新たな公式適合確認は行っておらず、監査の確認範囲は[AUD-006](../audits/2026-10-16/evidence-and-sources.md)を参照する。28日から365日へ設定だけで延長しない。

アプリ内の規約・プライバシー説明への安定した入口を用意し、API出所、保持範囲、送信範囲、素材利用の条件を説明する。必要な同意導線は実際の用途で確認する。権利者の許可・取得手段の許可・AI送信許可を別に扱い、チェック欄で権限を作らない。今回の段階Aでは無効な機能が起動せず、公開数値と許可範囲の単純計算・手動下書きは使えることを検証する。
