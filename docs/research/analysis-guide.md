## ノウハウを反映する質問テンプレート

以下は資料をもとにした本プロジェクトの提案。成功要因を断定するものではない。音楽の専門知識を要求せず、普段の言葉で回答できるようにする。

| 観点 | 画面の質問 | 回答の例／補助 | 見落としを防ぐ問い | 企画への接続 |
|---|---|---|---|---|
| 利用場面 | どんな作業・気分の人に向けた内容に見えますか？ | 夜の作業、読書、朝の支度。視聴者属性の事実とは分ける | タイトルの訴求ですか？コメントの一例ですか？自分の推測ですか？ | 自分の動画の用途を一文にする |
| 継続性 | 1本だけでなく、最近の複数動画にも再生されていますか？ | 取得済みの直近動画を確認する | まだ公開から時間がたっていないだけでは？ | 継続して試す候補を選ぶ |
| サムネイル | 最初に何が目に入りますか？ | 主役、文字、余白、明暗、構図など | 同じ特徴で再生数が低い動画もありませんか？ | 自分の画像で何を伝えるか決める |
| タイトル | どんな用途・体験を約束していますか？ | 作業向けか、静かな時間向けか | 見た目や音楽と約束がずれていませんか？ | 誰向けか伝わるタイトル案へ |
| 冒頭の音 | 最初にどんな音が入り、どんな気分になりますか？ | 静かに始まる、すぐリズムが入る、声がない | 実際に聴きましたか？楽器名は確かですか？ | 1曲目の制作・採用条件へ |
| 全体の音 | 続けて流したとき、気になる変化は何ですか？ | 音量差、急な盛り上がり、曲間など | 用途によっては、その変化が必要では？ | 避けたい音・必要な変化へ |
| コメント | 具体的な利用場面や要望は書かれていますか？ | 一般的な称賛ではなく内容を見る | コメントを書いた人だけの意見では？ | 次に試す体験・改善案へ |
| 反例 | 良さそうに見えた特徴を持つ、別の結果の動画はありますか？ | 似たタイトル・サムネイルで結果が異なる例 | 公開時期やチャンネル規模も違いませんか？ | 単一の原因に決めつけない |
| 自分の実行可能性 | 自分の予算・作業時間で用意できるのはどの部分ですか？ | 音楽、画像、編集の範囲を記入 | 継続するたびに大きな追加費用が必要では？ | 小さな試作の範囲を決める |

資料対応：[U1-a](../references/sources.md#u1-a) 比較・コメント、[U1-b](../references/sources.md#u1-b) 冒頭の音楽、[U1-c](../references/sources.md#u1-c) 自分の言葉で音を表す、[U1-d](../references/sources.md#u1-d) 視聴シーンと一致、[U1-e](../references/sources.md#u1-e) 変更を絞る、[U1-f](../references/sources.md#u1-f) 良い点・改善点・活用。

### 記録は4つに分ける

1. 観測：実際に見た・聴いた・取得できたこと。
2. 仮説：そこから考えた説明。事実と混ぜない。
3. 反例・不明点：同じ特徴でも結果が違う例、未観測の情報。
4. 次の確認・試作：費用を使う前に何を確かめるか、次の1本で何を変えるか。

例（架空であり、実データではない）：

- 観測：選んだ複数動画に小さな文字と大きな余白がある。
- 仮説：落ち着いた作業空間を期待させているかもしれない。
- 反例：同様の構図でも再生数が低い動画がある。競合CTRは不明。
- 次の確認：音楽・タイトル・公開条件の違いを確認し、自分の企画に必要な表現を決める。

「余白があるから伸びる」と確定しない。AIに文章化を相談した場合も、推測は確認済みの知識に昇格させない。

## ノウハウの管理方法

初回は設定ファイルまたはMarkdownで十分。専用の編集画面は不要。

各質問に `id / version / question / purpose / answer_examples / caution / source_ref` を持たせ、回答にテンプレート版を記録する。

資料の情報は以下の扱いに分ける。

| 区分 | 扱い |
|---|---|
| 観察・比較の手順 | 質問・比較画面の初期ガイドとして採用する |
| 投稿者個人の成功例・数値目安 | 事例として参照する。合否判定の初期値にしない |
| 推測されたアルゴリズムの説明 | 未検証の仮説として扱い、内部評価の事実にしない |
| 公式仕様・権利・利用条件 | 公式の現行資料を別途確認し、確認日を残す |
| URLと見出しだけで本文がない記事 | 未確認。記事内容を推測してガイドに埋めない |

例：資料にあるCTR4％・1時間動画の維持率40％は筆者自身の目安と明示されている。全チャンネル共通の成功閾値にはしない。[U1-g](../references/sources.md#u1-g)

ユーザー自身も「なぜ中央値の3倍か」「別のしきい値ではないか」を検証したいと記述している。初回から3倍を自動バズ判定にしない。[U3](../references/sources.md#u3)
