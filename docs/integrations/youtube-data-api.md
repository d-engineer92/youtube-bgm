## 取得の基本案

- `search.list`：候補の発見。検索条件と実行日時を保存する。[W3](../references/sources.md#w3)
- `channels.list`：公開情報とuploadsプレイリスト等を取得する。[U2](../references/sources.md#u2)
- `playlistItems.list`：指定した投稿一覧をページ送りで取得する。[W4](../references/sources.md#w4)
- `videos.list`：対象動画の公開情報を取得する。[W5](../references/sources.md#w5)

検索による発見と、選んだチャンネルの継続観測を分ける。日次更新のたびにすべてのキーワード検索を繰り返さない。

初回取得の件数上限は設定可能にし、続きがある場合は追加取得できる。`nextPageToken`に従う。途中取得なのに「全動画」「チャンネルの最初の投稿」と表示しない。検索の`totalResults`は概数であり、完全性確認やページ送りの根拠にしない。[W3](../references/sources.md#w3)

YouTube側のクォータは、実装時の公式資料と実プロジェクトの割当を確認する。旧資料の固定値をそのまま保証値にしない。手動更新にも同じ利用上限・エラー処理を適用する。上限超過時に別プロジェクトへ切り替える回避策は作らない。[W1](../references/sources.md#w1)

## 観測・エラー処理

- ウォッチ対象のみを原則日1回更新する設定案。ローカル停止中は観測できないため、実際の取得時刻で扱う。
- 冪等性：同一実行のリトライが観測点を水増ししない。別時刻の観測は別レコード。
- 一部失敗時は成功・失敗・未取得を分けて表示し、失敗を空データ成功として扱わない。
- 上限・タイムアウト・リトライ回数を設定し、無限リトライしない。
- APIキーはサーバー側の環境変数。Git、ブラウザー、ログに出さない。
- 公開情報の本文等は表示時にエスケープする。URLは許可した形式だけ処理し、任意URLをサーバーで取得しない。
