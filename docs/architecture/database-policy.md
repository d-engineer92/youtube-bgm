# PostgreSQLのみを使用するDB方針

> 文書ID：ARC-002  
> 状態：ユーザー指定の採用方針。実装への反映・再テストは未確認。  
> 読む場面：DB接続、環境構築、DB依存テスト、CI、バッチの保存先を変更するとき  
> 整理日：2026-10-14  
> 決定根拠：利用者の「DBは分けたくなく、PostgreSQLのみとしたい」という追加指示。

## 採用する構成

**アプリが使用するDBエンジンはPostgreSQLだけとする。開発・通常運用・DB依存テスト・CI・将来の分析結果取込に適用する。SQLiteはテスト専用でも採用しない。**

競合情報、調査メモ、制作指示書、将来取り込むローカル分析結果は、その環境の同じアプリ用PostgreSQLデータベースへ保存し、テーブルで責務を分ける。機能別にSQLiteや別エンジンの分析DBを追加しない。DBを使うキュー・キャッシュ・セッションも同じ方針とする。DBを使わない純粋な単体テストや一時的な配列・ファイル利用まで禁止する意味ではない。

従来文書の「PostgreSQLを採用する提案」は本指示で確定する。SQLiteで実施した過去のテスト記録は履歴として残してよいが、今後のサポート対象や実行手順にはしない。

## テストデータの安全な分離

DBエンジンは統一する一方、**自動テストを実データの入った通常運用DBへ接続しない。** テストでは初期化・削除があり得るため、同じPostgreSQLサーバー内の専用テストDB、または使い捨てのPostgreSQLコンテナーを使う。

例（実際の接続名は実装で確認する）：

```text
PostgreSQL
├── youtube_bgm          # 通常のアプリデータ。機能別にDBを分けない
└── youtube_bgm_test     # 自動テスト専用。実データを置かない
```

これは運用データを二つのDBへ分散する設計ではなく、テストの破壊的操作から守るための隔離である。テスト用ロールと権限も分け、通常DBの更新・削除を許可しない。DB名が `_test` で終わるというチェックだけに安全性を依存させない。

テスト起動時には、テスト環境であること、実効ドライバーが `pgsql` であること、実効接続先が明示的に許可したテスト用接続先であることを、マイグレーション・初期化より前に検査する。違反時は停止する。設定キャッシュや接続URLによる上書きも考慮する。CI・ブラウザーテスト・並列テストのワーカー用DBにも同じ条件を適用する。

## Codexへの修正指示

既存コードを確認したうえで、次の範囲を必要最小限で修正する。実装報告のテスト件数を、そのまま検証済みの事実として再利用しない。

1. `.env.example`、テスト用環境設定、`config/database.php`、`phpunit.xml`、テスト基底クラス、Docker構成、CI、Composerスクリプト、READMEの有効な接続経路を確認する。
2. DBを使う処理は `DB_CONNECTION=pgsql` を基本にし、PostgreSQL接続失敗時のSQLiteへの自動切替を作らない。SQLiteのテスト行列、`:memory:` のDB指定、SQLite用セットアップ・ファイル自動作成・アプリ独自分岐を取り除く。
3. DB依存テストはPostgreSQLだけで実行する。PostgreSQLが準備できない場合はエラーまたは未実行を明示し、SQLiteの成功で代替しない。テスト件数を合わせるために検証を削除しない。
4. 開発・CI・テストのPostgreSQLメジャーバージョンを揃える方針とし、実装で採用した値を一か所で管理する。対応バージョンは実装時に確認する。
5. SQLite専用のアプリ依存や設定を除去する。ただしフレームワークや依存ライブラリの内部コードを改変してまでSQLiteという文字を消さない。`vendor/` を編集しない。
6. 既存のSQLiteファイルに実データがあるかは未確認。データ入りファイルを削除・上書きしない。実データが見つかった場合は件数と用途を報告し、移行・照合・削除を別途承認された手順で扱う。
7. PHPUnit等の結果に加え、実際に接続したDBドライバー・テスト専用DB・PostgreSQLバージョンを確認して報告する。パスワードや接続URL全体は出力しない。

## ローカル素材分析との関係

[ローカル分析仕様](../local-analysis/README.md)のJSON・CSV・Markdownは、分析結果の受け渡しと再取込のためのファイルであり、第二のDBエンジンではない。ジョブの一時状態も既定のファイル方式のままでよく、SQLiteを追加しない。

LA-1・LA-2は引き続きファイル出力まで。今回の統一指示を理由にDB取込を前倒し実装しない。将来のLA-3では、既存アプリと同じPostgreSQLのDBへ取り込む。結果保存後の素材削除をDBの稼働や取込成功に依存させない。

## 受入確認（AC-13の詳細）

- 通常起動・バッチ・DB依存テスト・CIの実効接続先がPostgreSQLである。
- テスト実行中にSQLiteのインメモリDB・DBファイルが使用・作成されない。
- PostgreSQL停止時はDB依存処理が明示的に失敗し、SQLiteへ退避しない。
- 誤った通常DB設定でテストを起動しようとすると、破壊的処理より前に停止する。
- DB依存テストをPostgreSQLで再実行し、成功・失敗・未実行と実際の件数を報告する。
- 純粋な単体テストやローカル分析のファイル出力を、不必要にDBへ依存させない。
- 現存データ・自作素材・他プロジェクトのDBを変更・削除していない。
