# UI/UX監査と、最小限の画面再構成

> 文書ID：AUD-004 / 監査日：2026-10-16\
> 根拠：現行Blade/CSS/ルート/ブラウザーテストの静的確認。localhostの操作、画面画像の視認、実機での読みやすさ・アクセシビリティ測定は今回未実施。\
> 以下はコードで確認した構造上の問題と提案。未確認の見た目を確認済みとしない。

## 1. 既存画面で残す良い部分

未入力開始、US/en・JP/jaの任意切替、架空データと実データの分離、途中進捗・停止・再開、欠損と0の区別、元結果へのリンク、サムネイルと原題、焦点表示用CSSは残す。Laravel Bladeで改善でき、SPAへの全面移行やUIライブラリの総入替は不要。

## 2. 具体的な課題

| ID | 現行コードで確認したこと | 利用上の問題 | 改善案 |
|---|---|---|---|
| U-01 | explorationの先頭は条件数・API試行・期限・停止等の運用情報 | 収集完了後や翌日も「何が変わったか」より取得操作が前面 | 初回は探索開始、収集後は観測状況と変化一覧を主にする。詳細進捗は完了後折りたたむ |
| U-02 | 8テーマ×2条件を一つの縦長画面へ反復表示 | 多数を比較するために上下を往復し、説明・ボタンも繰り返す | サマリー＋テーマ絞り込み＋単一の対象一覧。取得条件別の見方は残し、全体の重複排除一覧も用意 |
| U-03 | 選択formが各lensごとに別 | 新着と再生数順、別テーマから選んだ2本をそのまま一緒に比較できない | ページ横断の共通選択トレイ。動画ID単位に重複排除。戻る／並び替えで維持 |
| U-04 | 各lensは先頭3本、それ以外はdetails。テーマ間に同じ動画が再登場 | 少数だけ見て判断しやすく、同じ作品を複数作品と見誤りやすい | 「全取得○本中の○本」と取得経路数を明示。フィルター・並び順と表示切替、サーバー側ページングを使う |
| U-05 | 現行では大量のカードを各セクションへ出し、通常一覧の並びは累計・公開時刻中心 | 低再生を保存する価値を、翌日の増分から見つけにくい | 主一覧は増分・観測間隔・公開経過・履歴・状態を中心に。初回のみを消さず「観測待ち」と区分 |
| U-06 | compare-gridはminmax(270px,1fr)、狭い画面では長いカードが縦積み | 同じ項目の比較に記憶とスクロールが必要 | PCは項目行を揃えた比較表＋サムネイル帯。スマホは2本の主要項目を対にし、詳細は対象切替。6本を極小表示しない |
| U-07 | 比較目的の入力が上、ガイド回答は未実装 | 何を見ればよいか不明なまま文章入力を求める | まず違いを見せ、資料由来の問い・回答例・反例欄を順に開く。未確認を許し、途中保存 |
| U-08 | comparison_typeは本人選択・初期値same_channel。Controllerは列挙値だけ検査 | 実際は別チャンネルでも「同一チャンネル比較」と保存できる | 対象channelIdから実際の関係を求め、表示・保存する。ユーザーが選ぶ分析目的とは別項目 |
| U-09 | 比較画面は最新2点、探索は24h条件の別ロジック | 同じ動画の「増分」が場所により違い、理由が分からない | 共通の期間・基準点を表示。時系列、一覧、CSV、JSONで同じresolverを使う |
| U-10 | readonlyのAPI情報と観察用説明、UTC、T0、run、read、hash等が多数 | 安全説明が重要な判断情報と同じ強さで並ぶ | 常時表示は出所・比較上重要な制約・稼働異常。技術詳細や長い注意は説明パネルへ |
| U-11 | 候補JSONの操作案内がCLI中心。helpに実装ブランチ固定URLがある | 操作場所が分断し、ブランチ削除後に説明が失われるおそれ | 実装版に対応する安定した文書リンク。固定依頼コピー→ファイル保存→検証→確認の流れを短く案内 |
| U-12 | テストは主に3動画、同一lensの最初の2本、ページエラーと横はみ出し | 多数の実データ、期間比較、横断選択、入力保持を証明しない | 130異なる動画の架空fixtureで一連の判断を実施。1000件で一覧処理も別途測る |

## 3. 再構成する利用導線

新しい巨大な管理画面群を作るのではなく、同じアプリの表示責務を整理する。

### 探す

未入力で開始。既にデータがあれば前回探索と「追跡結果を見る」を上に表示。新規発見と既存対象の更新を別操作として説明。全8テーマを選ぶ前提にせず、後から対象の探索条件を変更できる。

### 変化を見る（再訪時の主な入口）

追跡数・観測できた数・観測待ち・失敗・遅延・次回予定を一列にまとめる。本文は動画一覧。各行は、サムネイル、原題、チャンネル、公開後経過、今回再生数、前回からの増分と時間、短い推移、詳細／比較選択。検索順位は元検索の情報として残す。

切替は「比較可能な区間」「初回のみ」「欠測あり」「累計が多い」「新着」等。低再生を取得・追跡から排除しない。増分順も比較可能な区間だけに限定し、48hと24hを無説明で混ぜない。全体の見える数と各区分の対象数を表示する。

### 並べて理由を考える

共通トレイから2〜6本を選ぶ。現在値と固定した比較時点を切り替え、同じ条件で見た事実、別の説明、音や画像を実際に確認したかを記録する。サムネイルと動画フレームは別欄。元の一覧へ戻っても選択・条件・スクロール位置・下書きを可能な範囲で保持する。

### 次の一本へ

比較で採用した仮説を、短い制作指示書へ明示的にコピー／参照する。自作の用途、変える一要素、音楽・画像・タイトルの整合、試作上限、確認方法を下書き保存する。対象動画・観測・素材分析結果の関係を失わせない。生成・投稿は手動のまま。

## 4. 表示と操作のルール

- 「更新成功」だけでなく、いつからいつまで、何件成功し何件は不明かを出す。
- 検索地域US、想定ペルソナ、チャンネル設定国、実際の視聴者国を別項目とし、混同しない。
- 「伸びた理由」ではなく「確認した変化」「考えられる理由」「次の確認」を使い分ける。
- 初期状態・初回のみ・0増分・非返却・失敗・停止・期限外・予算待ちの全状態で次の行動を示す。
- 文字はPCでも読める寸法、数字は桁区切り、長文は展開、単位・期間を省略しない。現行CSSの小文字が実機で読めるかは実測する。
- 色だけで状態を区別しない。キーボード、フォーカス、ラベル、200%拡大、長い日本語／英語タイトル、画像欠損も試す。
- 2件未満／6件超の選択理由をその場で表示する。保存中・保存済み・未保存を区別し、自動更新で入力を消さない。
- 規約・プライバシー・保持範囲は一か所の正本へリンク。毎カードに長文警告を複製しない。
