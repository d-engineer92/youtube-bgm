# 全取得動画を初回から自動追跡する

> 文書ID：TRK-001\
> 状態：2026-10-16の利用者指示を反映した改修仕様。未実装・DB未消去。\
> 読む場面：取得後の追跡・履歴表示・切替を実装するとき。\
> 確認したmain：`c2060e2eff02d7dfe35ffbb2d7c70544b0e52076`

## 今回の確定方針

**新着も0〜一桁再生も取得する。取得した動画は手動ウォッチ不要で初回から追跡し、翌日以降の実測値を蓄積して、伸びた動画・伸びなかった動画を比較する。改修の利用切替時に旧調査データを全消去し、新方式で収集を開始する。**

前の会話で提案された「新着を減らす」「1,000再生などで足切りする」「選んだ動画だけ追う」「7日で自動追跡を終える」は採用しない。低再生だけを非表示にする修正でもない。

利用者の元の判断軸には日次の再取得と差分の蓄積がある。今回の変更は収集結果を判断材料にするための欠落を埋めるもの。再生数が増えた原因は、差分だけでは確定しない。画面・比較・必要なAIへの受け渡しで検証を進める。

## 維持するものと変えるもの

| 項目 | 方針 |
|---|---|
| 未入力の探索入口 | 8テーマ×再生数順/新着順、計16検索ページを維持。US/en初期値・JP/ja切替・日本語案内も維持 |
| 取得・保存の条件 | 再生数の下限は追加しない。0は値、欠損はNULL。既存の尺・期間・検索条件は維持 |
| 追跡対象 | 探索、手動検索、関連語、古い作品、URL登録、投稿一覧等から登録した全動画。関連チャンネルの公開統計も日次更新 |
| ウォッチ | お気に入り・比較用の選択として残す。日次取得対象の選別には使わない |
| 更新 | 同一動画IDの情報を約24時間ごとに再取得。再検索して別の動画に置き換えない |
| 保存 | 現在値と取得時点の履歴を分け、各観測は取得時刻付きで追記する |
| 分析 | 段階Aは一覧の実観測差分・時系列・比較・期限付き出力契約。段階Bは既存ガイドの最小保存→採用仮説→試作下書き。AIは条件確認まで無効 |
| 切替 | 旧データの引継ぎや後付け追跡を行わず、承認済みの一回限りのリセットで再開始 |
| 技術 | Laravel・同じPostgreSQL・DBキュー。SQLite・有料AI・別DBは追加しない |

「全動画」はアプリが発見・登録した範囲であり、YouTube全体や当該チャンネルの未取得投稿すべてを意味しない。自分の動画も、公開APIで取得できる範囲は同じ仕組みで0再生から追う。

## 完成条件

`新規取得 → 初回実測＋自動追跡登録 → 人がウォッチを押さず翌日再取得 → 履歴追記 → 差分・欠測・グラフを表示 → 比較または分析用出力`

これと[安全なリセット・再開始](reset-cutover.md)を一つの改修として完成させる。バッチだけ、グラフだけ、DBの消去だけで完了としない。

## 旧仕様との優先関係

今回の対象では、EXP/FTR/INT/RESの「手動ウォッチした動画だけを追う」部分をTRKで置き換える。EXPの新着取得は維持する。「既存データを初期化しない」は今回だけTRK-004の明示承認された切替に置き換える。通常マイグレーションや起動時の自動初期化は禁止のまま。

[PostgreSQL専用方針](../architecture/database-policy.md)と[保存期限の共通方針](../compliance/data-retention.md)は維持。追跡が続くことと、古い観測値を無期限に保存できることは別。現行の競合履歴は28日ローリングであり、長期保存の追加許諾は未取得。28日で追跡自体を終了させない。

LA-1/LA-2、音源ファイル、制作・投稿、有料AI接続、LA-3は変更しない。旧作業2全体は追加せず、RES-001/FTR-003の最小接続のみ段階Bとして採用する。無制限の新規探索や自動日次新規検索も今回追加しない。
