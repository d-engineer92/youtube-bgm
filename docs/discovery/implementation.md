# Codex実装依頼・受入条件

> 文書ID：EXP-006\
> 状態：EXP-A・EXP-B実装済み／2026-10-14。[検証記録](verification.md)。\
> 読む場面：実装の開始・分割・PRレビュー・完了報告。

## 依頼の目的

既存mainの手動検索中心の入口を、キーワード・ジャンル・用途が未定でも使える「おまかせ探索」にする。英語圏想定を初期値にし、画面・語の意味・判断の案内は日本語。日本向けへ任意切替可能とする。

## 実装順

### EXP-A：入口から結果選択まで

1. AGENTS、[専用入口](README.md)、[DB方針](../architecture/database-policy.md)、[保存条件](../compliance/data-retention.md)を確認。
2. [カタログ](../../config/discovery-catalog-v1.json)をruntime configへ移し、読み込み検証・版/ハッシュ管理を実装。docsには正本へのリンクを残す。
3. 保存型プランナーと最小の追加DB、PostgreSQL DBキュー、単一ワーカーを実装。開始/停止/再開/進捗と二重実行防止。
4. Collector/ApiCallerの共通基盤を拡張し、地域・言語・UTC期間・1ページ取得・詳細のみ再開・run予算を対応。検索エンジンを別実装しない。
5. 画面Aの最上部に探索入口、テーマ別結果、意味・不明点・次の操作を追加。既存比較/ウォッチ/手動検索へ接続。

### EXP-B：深掘り・拡張・運用確認

6. 古い作品の追加検索、related語からの1クリック深掘り、候補JSONのdry-run/applyと承認/保留を追加。
7. 期限・部分失敗・復旧・デモ分離・予算・実際の検索パラメーター・初心者のブラウザー導線を確認。
8. 新規cloneと既存環境の両方で起動手順を整備。通常起動にワーカーを含め、停止時の案内を確認。統合後のアプリCIとローカル分析CIを両方実行。

A/Bを分けてPRにする場合も、今回の受入はBまで。旧作業2（制作指示書全体）、LA-3、音声DL連携、有料AIを追加しない。統合先は最新main、今回の文書が未マージならまず文書を取り込んでから実装用の別ブランチを作る。マージは明示指示があるまで行わない。

## 実コードで確認する変更候補

- resources/views/discovery.blade.php、ResearchController：入力必須の手動フォームは保持し、新しい未入力開始の導線を追加。
- Collector::searchParameters/pages/hydrate、GoogleGateway/ApiCaller：確定条件、ページ境界、詳細再開、共通予算。`reset()`でrun予算を失わない。
- config/youtube.php：既存の日次20検索/500read設定を維持。探索用設定を別責務で追加。
- FetchRun/RunItem/Retention：出どころ・検索順・期限・動画件数。既存の取得ID・統計を再利用。
- compose.yaml、queue設定、DBキューマイグレーション、README：PostgreSQLだけの非同期ワーカー。
- テスト、docs/README、FTR-001、INT-001、DEV-001/002、AGENTSの実装状況：変更後の正本と手順を同期。旧実装記録を消して書き換えない。

## 受入条件

| ID | 必須確認 |
|---|---|
| EXP-AC01 | API初期設定後、利用者がq/ジャンル/用途を入力せず主ボタンだけで8テーマの計画が開始する。単なるプリセット語ボタンの一覧で終わらない |
| EXP-AC02 | 初期US/en、日本JP/jaの全検索パラメーターがGatewayまで届き、結果画面で実行条件を確認できる。二つを自動同時実行しない |
| EXP-AC03 | T0・辞書版・実際の語・30日/180日/5年の境界・long条件が固定。再開で日付が動かず、JST endOfDay変換でずれない |
| EXP-AC04 | 初回8×2の16ページ。1ページ10件。nextPageTokenがあっても勝手に2ページ目へ進まず、最大160は重複込みのヒット上限だと表示 |
| EXP-AC05 | 結果をテーマ/検索条件別に表示。原題・サムネイル・数値・取得時刻・英語の意味・次の操作があり、最近の上位と新着を区別 |
| EXP-AC06 | 同じ動画が複数条件で返るfixtureで動画レコード/総件数を重複させず、全検索経路を追える。チャンネル行を動画件数へ加えない |
| EXP-AC07 | 0件成功、部分失敗、キーなし、quota、未観測、期限切れを区別。「需要ゼロ」「高単価国の人気」「成功確実」等へ変換しない |
| EXP-AC08 | 予算を低くしたテストで手動/探索/再試行/深掘りが共有日次枠を超えない。Collector reset・並列投入後もrun上限を超えない |
| EXP-AC09 | 検索成功後の詳細取得失敗では検索済みページを再取得せず、同一task/FetchRunの未解決IDだけを再開する |
| EXP-AC10 | 二重クリック・重複ジョブ・ワーカー強制停止・busy・停止/再開で対象や観測が重複せず、成功結果を破棄しない。送信後保存前の消費不明も明示 |
| EXP-AC11 | 最初のHTTP応答は全API取得を待たない。画面を閉じても進む。GET/ポーリングは新規API取得を起動しない。worker停止を無言で放置しない |
| EXP-AC12 | 動画の初回取得や短間隔の2回取得を日次増加としない。改修後はRES-002の共通区間契約（22〜26h、範囲外は別区分）・負の差分・欠損・観測停止をfixtureで検証 |
| EXP-AC13 | 古い作品とrelated語の深掘りを、入力不要の操作で開始できる。低再生作品を隠さず、元の結果と比較へ戻れる |
| EXP-AC14 | 候補JSONのdry-run無変更、apply原子性、重複、未知キー、誤型、上限超過、UUID競合、未承認は未実行を検証。新テーマNULL親も扱える |
| EXP-AC15 | 候補JSON取込・結果画面閲覧は有料AI、素材DL、YouTubeサジェスト、モデルAPI、分析スキルを呼び出さない |
| EXP-AC16 | 28日期限を検索所属/順位/キャッシュ/キューへ適用。期限切れrunを再開せず、純粋な本人の企画を巻き添えで消さない |
| EXP-AC17 | demo/live・US/JPを混同せず、同一live動画の再生数は全世界の値として共有。デモデータをlive観測へ投入しない |
| EXP-AC18 | PostgreSQL専用CIでテスト。通常DBへの誤接続を初期化前に拒否。既存手動検索・直接登録・比較・ウォッチ・LA-1/LA-2を回帰確認 |
| EXP-AC19 | PC/スマートフォンで未入力開始→進捗→テーマ→2〜6本比較→ウォッチ→古い作品または別語を実際に操作。デモだと明示した画面証跡を残す |
| EXP-AC20 | 実キーがある場合だけ少数の実API疎通を実施し、送信条件・件数・時刻・使用枠を報告。未提供ならモックと実APIを分け、需要検証済みと書かない |
