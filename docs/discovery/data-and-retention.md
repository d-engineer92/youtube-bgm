# 探索データ・観測・保存期限

> 文書ID：EXP-004\
> 状態：EXP-A・EXP-B実装済み／2026-10-14。[検証記録](verification.md)。\
> 読む場面：マイグレーション、重複排除、結果表示、継続観測、期限処理。

## PostgreSQLだけを使用する

[ARC-002](../architecture/database-policy.md)を適用する。同じアプリDBに追加し、SQLite・別分析DB・Redisは導入しない。DBテストは専用PostgreSQL DB/制限ロールを使用し、通常DBを初期化しない。

## 最小の論理モデル

名称は既存規約に合わせて調整可。新規は探索実行・タスク・候補語を基本とし、動画統計の複製テーブルは作らない。

| 領域 | 最低限の情報 |
|---|---|
| explorations | UUID、source=demo/live、preset_id、catalog_version/hash、T0、実行条件、状態、idempotency key、検索/read試行累計、停止理由、開始/終了、expires_at |
| exploration_tasks | exploration_id、theme/candidate ID、lens、確定q・regionCode・relevanceLanguage・UTC期間・尺・ページ上限、順序、状態、fetch_run_id、claim/lease、試行数、エラー、nextPageToken/has_moreへの参照、expires_at |
| exploration_keywords | 候補UUID、親テーマ（NULL可）、日本語名/説明、preset_id、q、正規化キー、提案元、提案理由、proposed/approved/held/disabled、取込版、承認日時、由来と期限の管理 |
| 既存FetchRun/RunItem | 1タスクの取得実体。検索ヒットの順位と種別を必要なら追加。動画詳細の解決状況とチャンネル詳細を区別 |
| 既存Target/Video/Channel/Observation | 現行値・動画単位の観測値。探索別に複製しない |
| Laravel DB queue | jobs/failed_jobs等。payloadは内部IDだけを基本としAPI本文を複製しない |

必須制約：Targetの(source,kind,external_id)、タスクの(exploration_id,task_key)、FetchRunとの安定した紐付け、候補の(source,preset_id,normalized_query)。一つの動画が複数テーマに現れる検索経路はRunItem経由で残し、同一テーマ内の表示件数と全体件数は重複排除する。

## 地域・言語・デモの分離

preset_id、要求したregionCode/relevanceLanguage、APIが返したregionCode（返らなければNULL）を記録する。不一致なら表示し、要求値で取得できたと偽装しない。これらは検索条件であって実際の視聴者国・単価ではない。視聴者国や推定RPMのカラムを新設しない。

同じ動画IDがen-US/ja-JPの両方で返っても、liveの公開統計は動画単位で共有可能。検索の所属は分ける。世界全体の公開再生数をUS再生数・JP再生数として別々に作らない。

demo/liveは既存source分離を維持する。架空動画や架空の数値をliveの履歴へコピーしない。統計・結果を輸入する入口として候補語JSONを使わない。

## 観測と比較

- 探索は新しい候補を見つける作業。ウォッチは同じ対象の変化を記録する作業。初回探索はwatch=falseを維持し、利用者が選んだ動画だけを登録する。
- 既存のウォッチ更新を利用する。動画ウォッチなら当該動画を追い、チャンネルウォッチなら新規投稿を含む別スコープだと区別する。
- 2観測の差分は実時刻付きで示す。今回の探索内で同じ動画を数分差で複数取得しても「日次成長」と呼ばない。日次の参考表示は24時間以上離れた有効な観測点がある場合だけにし、実際の時間差を併記する。24時間は表示上の設計値である。
- NULL・ゼロ・負の差分・API失敗は別扱い。補間・過去の復元・負数のゼロ丸めはしない。新規動画公開数と検索で見つけた数を同一視しない。
- 今回はテーマ単位の需要成長率や総合順位を作らない。今後集計する場合も固定対象集合・観測期間・欠損分母の仕様が先に必要。
- 古い作品の累計再生数だけで継続需要と判定しない。直近の増分確認へ案内する。どの数値も、そのテーマで新規参入した場合の成功確率ではない。

## 期限と再開

保存期限の正本は[POL-001](../compliance/data-retention.md)。今回も既存28日設定を使い、観測点の取得日を更新して延命しない。

検索ヒット所属・検索順位・トークン・API由来の件数や表示要約・タスクに保持したAPIエラー情報等にもexpires_atを適用する。検索時点の所属を、動画の現在値更新だけで無期限延命しない。期限切れは画面・CSV等から除外して削除する。

外部由来の期限が異なるものを結合した表示は、期限切れの根拠を表示しない。取得済み履歴の削除と、本人の比較目的・探索語の削除を不必要に連動させない。一方、本人メモという名前でAPI本文や数値を隠して保持しない。

辞書・プロンプト・本人の純粋な企画仮説はAPIキャッシュと別。API由来の候補や転載文章が混入した場合は由来と期限を検査し、今回の候補語インポートではAPI本文・数値・外部IDなどの余分なキーを受け付けない。

検索結果が失効した実行は再開不可。「結果期限切れ／同条件で新しく調べる」を表示する。新しい検索には新run/新T0を作る。DBキューとfailed_jobsに失効payloadやAPIデータが残らないよう期限処理を整備する。読み込み・再起動時の既存期限処理を維持する。

## 変更する際に守るもの

マイグレーションは追加的に行い、既存データ・比較目的・観測履歴を勝手に削除しない。テストデータを通常DBへ投入しない。APIキー、原本記事、取得メタデータ、実結果、ログを公開Gitに入れない。
