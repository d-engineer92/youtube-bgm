# 分析プロファイル v1

> 文書ID：LMA-003  
> 状態：初期の測定・解釈仕様。各数値はプロジェクトの提案条件。  
> 整理日：2026-10-14  
> 読む場面：FFmpeg計測、追加解析、画像観察、比較を実装するとき。

## 1. 固定する範囲

プロファイルIDは `analysis-profile-v1`。採用した設定を機械可読ファイルにし、SHA-256を結果に記録する。窓幅、無音条件、チャンネルの扱い、サンプリング、ライブラリ版を変更したら版を上げる。分析中にCodexが設定・計測コード・固定プロンプトを変更しない。

音声は元ストリームのサンプルレートとチャンネルを保持して計測する。音量正規化・圧縮・ノイズ除去後の音を元音源の測定結果としない。追加の単一チャンネル・低サンプルレート解析が必要なら変換条件を別記する。

## 2. 初回必須の計測

| metric | 内容・単位 | 範囲と注意 |
|---|---|---|
| duration_seconds | 実体の音声尺・s | ffprobeを利用。メタデータの宣言尺だけで完了を決めない |
| integrated_loudness_lufs | 統合ラウドネス・LUFS | 全編、EBU R128に対応するFFmpegの計測を使用 |
| loudness_range_lu | ラウドネスレンジ・LU | 全編。短尺・無音など算出不能は理由付きnull |
| sample_peak_dbfs | サンプルピーク・dBFS | 全編。true peakと混同しない |
| true_peak_dbtp | 推定トゥルーピーク・dBTP | 全編。オーバーサンプリング等の計測設定を記録 |
| silence_total_seconds | 条件に該当する無音の合計・s | 全編。同時無音区間の和集合を使い二重計上しない |
| leading_silence_seconds | 冒頭から続く条件該当無音・s | 最小無音長未満は検出されない点を注記 |
| trailing_silence_seconds | 終了直前の条件該当無音・s | 全編無音の場合、冒頭・末尾値を合計無音に再加算しない |
| rms_dbfs | 非重複10秒窓のRMS・dBFS | 最後は残り秒数。チャンネル別平均二乗を平均後に平方根、20log10で計算 |

無音の初期設定は全チャンネルが-50 dBFS未満で0.5秒以上。測定器の振幅・窓の定義も設定に記録する。検出区間は `silence_interval_seconds` の行に開始・終了と長さを保存する。これは曲の区切りを確定する判定ではない。

FFmpegのebur128、astats、silencedetect等は利用候補。採用したフィルター・設定とstdout/stderrのパースをテストする。音量を加工するフィルターの出力を測定元へ上書きしない。[公式資料](sources.md)

NaN、Infinity、-InfinityをJSONへ出さない。無音で対数値が定義できない場合は `kind=unavailable, value=null, reason=all_silence` 等とする。nullを0にしない。全編デコード失敗は必須計測の未完了であり、完成結果として確定しない。

## 3. 初回は追加オプションとする音楽的特徴

テンポの推定BPM、スペクトル重心・帯域比率等は、基本計測が役立つことを確認してから追加してよい。導入する場合、式、単位、サンプルレート、窓・hop長、実装版を固定する。

サンプリング案は冒頭60秒・中央60秒・末尾60秒。短尺では区間を切り詰め、重複を統合して実際の区間を記録する。全編測定とは別のcoverageにする。テンポには半分・倍の解釈や拍の弱い曲での不安定さがあるため `estimated` とし、失敗ならnull。

初回は楽器識別、コード進行、キー、ジャンル、感情、歌声の有無を自動確定しない。計測していない項目はlimitationsへ明記する。テンポ推定がないのにタイトルからBPMを埋めない。

## 4. 視覚分析は明示オプション

既定のaudioモードでは映像とサムネイルを取得せず、視覚評価を未実施と記録する。audio_visualモードは、権利・Codexへの画像送信条件と、実際の画像入力機能を確認してから使う。

フレーム時刻案は0、5、10、30秒、中央、終了1秒前。尺の範囲内へ制限し、重複を除く。実際に抽出できたPTSも保存する。サムネイルは別の画像で、動画の先頭フレームをその代わりと呼ばない。

主役、余白、文字、構図、明暗、用途の訴求を観察する。実際に読み込んだ画像IDだけ `viewed_evidence_ids` に記録する。未入力画像について所見を出さない。数枚のフレームから全編静止画・点滅なし・全編同一構成とは断定しない。

画像・切り出したフレーム・サムネイルは結果確定後に削除する。結果には画像ID、時刻、ハッシュ、観察文だけ残す。削除後は同じ画像の再確認ができないことをlimitationsへ記録する。

## 5. 観察と考察

実測値は `measured`、テンポ等の推定は `estimated`、画像を見た記述は `visual_observation`、人の試聴メモは `human_observation`、説明や改善案は `hypothesis` とする。推論に確率らしい数値を付けない。

固定の問い：冒頭と本編の音量差、途中の変化、曲間候補、終了部分、見た目と用途の一致、良い点、改善候補、別の説明、次の1本で試すこと。良い点と悪い点を必ず埋めるための創作はしない。

追加の気づきは0〜3件。定型項目外でも、証拠、別の説明、次の確認があるものだけ出す。再生数・順位を初期特徴抽出へ渡さず、必要な実績比較は別工程にして後付け解釈を減らす。

## 6. 自作と競合の比較

同じプロファイル・区間・取得品質を可能な限り揃える。自作マスターとYouTubeから取得した再圧縮音源は異なるため、違いを作品固有の品質差と即断しない。自作の公開版とマスターも別sourceとして保持する。

音量が小さい＝睡眠向き、高域が多い＝楽しい、差が小さい＝集中できる、という合否判定は作らない。広告挿入やプレイヤー側の音量処理を含め、ローカルファイルが実際の視聴体験を完全に再現するとは扱わない。競合のCTR・維持率・収益・成功理由を音源だけで推定しない。
