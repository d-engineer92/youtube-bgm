# 画面B：並べて分析する

> 文書ID：FTR-002  
> 状態：公開情報比較まで作業1実装済み（ガイド・観察回答は作業2、実データ未確認）\
> 読む場面：比較画面・観察入力・YouTubeへのリンクを作るとき  
> 整理日：2026-10-14  
> 元資料：[初回実装仕様 v2](../archive/codex_research_first_mvp_v2.md) L72–L85。見出し・参照リンクを整理し、要件の内容は引き継いでいる。

2〜6動画程度を並べ、サムネイル・タイトル・尺・公開日時・公開数値・取得時刻を同じ画面で見る。表示件数はUI上の目安で、分析上の正解ではない。

- 再生数の多い動画だけでなく、比較対象として少ない動画も選べる。
- 同一チャンネル内比較と、複数チャンネル間比較の目的を区別して記録する。
- 公開後の経過時間、尺、ライブ等の形式の違いを表示する。比較条件の差があるだけで誤りとはしないが、解釈の注意を表示する。
- 人気順・新着順・古い順は、対象が「取得済み範囲」である場合、その旨を常時明示する。
- 動画はYouTubeで開いて視聴できればよい。初回はプレイヤーを自作しない。
- コメントはYouTubeで人が確認し、利用場面・要望・不明点を自分の言葉でメモする。投稿者の個人情報やコメント全文を大量保存しない。
- 音楽のテンポ・楽器等は、実際に聴いて記入する観察欄。未試聴のURLやタイトルだけから音楽内容を補完しない。

「分析してみましょう」という空欄だけのUIは禁止。分析ガイドの説明付き質問を表示する。

## 監査反映の比較操作（段階A/B、実装済み）

[FTR-001の共通トレイ](discovery.md)から2〜6本を渡す。PCは項目行が揃う比較表とサムネイル帯、スマホは2本の主要項目を対にし、詳細は対象切替とする。6枚を極小化しない。実際のchannelId集合から同一/別チャンネルを算出・保存し、本人の比較目的と分離する。偽のsame_channel送信でも実関係を保存する。

現在値と固定比較時点を明示的に切り替える。保存契約は[TRK-003](../tracking/review-and-export.md#6-比較ai結果試作の参照契約切替前に確定操作は段階b)、期間の正本は[RES-002](../research/metrics.md)。期限切れ根拠を現在の値で補完しない。

段階Bでは数値の違いを先に見せ、[RES-001](../research/analysis-guide.md)の質問・回答例・反例欄を順に開く。「確認した変化」「考えられる理由」「次の確認」を別入力にし、未確認と途中保存を許す。戻る・並び替え・進捗更新で入力を消さず、保存状態と元一覧への復帰を示す。採用仮説から[FTR-003](production-brief.md)へ参照を保って進む。
