## 目的とユーザーの制約

ユーザーはAI×BGM・YouTube投稿ともに初めて。実装はCodexへ依頼する。成果が不明な段階で、楽曲生成費用と開発量を増やしたくない。ただし競合調査は、判断に使える深さを確保したい。

初回に作るのは「自動BGM工場」でも「成功判定AI」でもない。

> 競合の公開情報を比較し、説明付きの質問に沿って観察を記録し、何が未確認かを把握し、予算内で試す1本の制作指示書を作れる道具。

初回の完了は売上・登録者数ではなく、上記の一連の作業ができること。収益化の可能性は、競合データのみでは証明できない。公開後の自分の実績で更新する。

## 初回に作らないもの

- 楽曲生成API、画像生成API、有料LLM APIの接続。
- 楽曲・画像の大量生成、生成サービスの自動操作。
- FFmpegを組み込んだ制作パイプライン、動画アップロード、自動公開・予約投稿。
- OAuth、Analytics / Reporting API、自分のStudio CSVの汎用インポーター。
- 競合の推定売上、推定収益化状態、推定CTR・視聴維持率、成功確率。
- 独自の総合点、バズ点、アルゴリズム評価点、無許可の自動分類・感情分析。
- 自動コメント大量収集、全YouTube巡回、推薦欄のスクレイピング、競合音声のDL・抽出。
- 複数チャンネルの一括運営、通知連携、課金・権限管理、複雑な実験管理基盤。
- ノウハウ用の検索拡張生成（RAG）、ベクトルDB、汎用ワークフローエンジン。

権利確認と費用記録は省かない。ただし初回は制作指示書の記入欄でよく、専用管理システムは作らない。

## 別枠で依頼された追加範囲：ローカル素材分析

2026-10-14の追加ユーザー指示に基づき、[ローカル素材分析](../local-analysis/README.md)を別PR・別の受入条件で実装する。上記の対象外一覧は、進行中の検索・比較基盤の初回スコープを指す。

追加範囲に限り、利用条件を確認した競合素材・自作素材のローカル取得、FFmpeg等による読み取り分析、固定Codexスキル、結果ファイル出力と一時素材削除を扱う。未確認素材の取得、利用制限回避、大量巡回、制作・投稿、有料AI API接続は引き続き対象外。

追加分析のPython補助CLIは許容するが、アプリ本体をLaravel/PostgreSQL以外へ置き換えない。今回の追加を理由に、進行中の初回作業を止めたり完了条件を増やしたりしない。実装がない状態でスキルを有効化しない。

## 最小の利用フロー

候補を探す → ウォッチ対象を選ぶ → 比較対象を並べる → ガイドに沿って観察する → 仮説・反例・不明点を整理する → 1本分の制作指示書を保存する。

制作・編集・公開は別途手動。公開後はまずYouTube Studioを直接確認し、制作指示書の振り返り欄に記録する。繰り返し入力が負担になった時点でCSV取込を検討する。

初期の運用例は「候補10〜20チャンネル、詳しく見る3〜5チャンネル、同条件の複数動画」。これは作業量を抑えるための仮置きであり、統計的な必要標本数・成功条件ではない。候補不足を理由に必須件数を捏造しない。
